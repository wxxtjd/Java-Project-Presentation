
# 5팀 학식 메뉴 재고 확인 프로그램 발표 대본  

---

# Slide 1

안녕하세요.  
저희는 **학식 메뉴 재고 확인 프로그램**에 대해 발표하게 된 5팀의 **최완호님과 황준성**입니다.

---

# Slide 2

다들 교내 주요 식당에 가보셨죠?  
저도 자주 가봅니다.

그런데 인기 메뉴가 있는 날에는 조금만 늦게 가도 메뉴가 품절되어 있거나, 식권을 사고 들어갔는데 갑자기 품절되는 경우가 있었습니다.

이런 경우 시간도 낭비되고, 다른 메뉴를 골라야 하는 불편함이 생깁니다.  
그래서 저희는 학생이 미리 메뉴 재고를 확인할 수 있고, 누구나 직관적으로 사용할 수 있는 프로그램을 만드는 것을 목표로 했습니다.

---

# Slide 3

저희 팀의 역할은 이와 같습니다.

김지수님은 일정 관리와 요구사항 정리를 맡았습니다.  
저는 Main, Student, Cook 같은 주요 프레임을 구현했습니다.  
최완호님은 MenuData 관리와 파일 입출력 로직을 설계했습니다.  
뉘우샹유엔님은 기능 검증과 발표 자료 구성을 맡았습니다.

---

# Slide 4

개발 환경은 Windows 11과 Mac OS 15를 사용했습니다.  
GUI 구현을 위해 Java Swing과 AWT를 사용했고, 개발 도구는 Eclipse와 IntelliJ를 사용했습니다.

외부 라이브러리는 사용하지 않고 Java 표준 라이브러리만 사용했습니다.  
협업은 노션과 깃허브를 활용했고, 재고 데이터는 MealV4_data.txt 파일에 저장했습니다.

---

# Slide 5

실행 방식은 Main.java를 실행하면 시작 화면이 나오는 방식입니다.  
이 화면에서 학생 또는 조리사를 선택할 수 있습니다.

조리사 화면은 아무나 접근하면 안 되기 때문에, 코드를 입력해야 들어갈 수 있도록 만들었습니다.

AI는 ChatGPT를 사용했으며, 코드 구조 파악, 구현 정리, 발표 자료 문장 다듬기에 활용했습니다.

---

# Slide 6

프로젝트는 학식당에서 겪은 불편함을 바탕으로 요구사항을 정리하는 것에서 시작했습니다.

그 뒤 GUI 화면을 설계하고, 데이터 구조와 파일 저장 구조를 구현했습니다.  
마지막으로 기능 테스트와 발표 자료 정리를 진행했습니다.

---

# Slide 7

설계 구성 요소는 목표 설정, 합성, 분석, 제작, 시험, 평가 항목으로 나누어 확인했습니다.

학생이 재고를 조회하고, 조리사가 재고를 수정할 수 있는 GUI를 목표로 했고,  
메뉴 추가, 삭제, 재고 수정, 파일 저장 후 재실행까지 테스트했습니다.

---

# Slide 8

현실적 제한 조건도 고려했습니다.

별도 서버나 유료 라이브러리를 사용하지 않아 경제성을 확보했습니다.  
또 조리사 화면은 코드로 접근을 제한했고, 학생 화면은 재고 상태를 색상으로 보여주어 직관성을 높였습니다.

---

# Slide 9

프로젝트는 코드 약 1500라인, 클래스 및 인터페이스 8개로 구성되어 있습니다.  
UI는 총 29개의 메뉴 화면으로 되어 있고, 데이터는 MealV4_data.txt 파일과 연동됩니다.

주요 구현으로는 Swing 기반 GUI, Timer를 이용한 1초 단위 시계 갱신, MenuData의 싱글톤 패턴, 파일 입출력 예외 처리가 있습니다.

---

# Slide 10

이제 시스템 구성도를 보겠습니다.

전체 프로그램은 Java Swing 기반의 MealV4 프로그램으로 구성되어 있습니다.  
사용자는 크게 학생과 조리사로 나뉩니다.

학생은 StudentFrame을 통해 메뉴, 가격, 재고, 운영 상태를 조회합니다.  
조리사는 CookFrame에서 로그인 후 판매 처리, 재고 수정, 메뉴 추가와 삭제, 운영 시간 설정을 할 수 있습니다.

가운데의 MenuData는 싱글톤 데이터 허브로, 메뉴 데이터와 운영 시간, 비밀번호를 관리합니다.  
그리고 수정된 내용은 MealV4_data.txt 파일에 저장되고, 다시 실행할 때 불러와집니다.

---

# Slide 11

다음은 프로그램 다이어그램입니다.

프로그램은 Main.java에서 시작되고, MainFrame이 메인 컨트롤러 역할을 합니다.  
MainFrame은 로그인, 화면 전환, 데이터 연동을 담당합니다.

왼쪽의 Model 부분에는 MenuData, MenuItem, OperationStatus가 있습니다.  
MenuData는 전체 데이터를 관리하고, MenuItem은 메뉴의 이름, 가격, 재고, 코너 정보를 담습니다.  
OperationStatus는 시간에 따라 준비중, 운영중, 마감 상태를 판정합니다.

가운데 View 부분은 StudentFrame과 CookFrame입니다.  
학생 화면은 메뉴와 재고를 조회하고, 조리사 화면은 재고와 메뉴를 수정합니다.

오른쪽 Utility 부분에는 MealV4_data.txt 파일, Displayable 인터페이스, Java Swing과 AWT가 있습니다.  
즉, 데이터, 화면, 유틸 기능을 나누어 관리하도록 구성했습니다.

---

# Slide 12

데모 흐름은 간단합니다.

먼저 프로그램을 실행하고 시작 화면을 확인합니다.  
그다음 조리사 로그인을 통해 재고를 수정합니다.

이후 학생 화면에서 새로고침을 눌러, 수정된 재고가 반영되는지 확인합니다.  
즉, 조리사가 관리하고 학생이 조회하는 전체 흐름을 보여드리겠습니다.

---

# Slide 13

데이터 저장은 별도 데이터베이스 없이 텍스트 파일로 처리했습니다.

파일 이름은 MealV4_data.txt입니다.  
이 파일에는 장소별 운영 시간과 메뉴 정보가 저장되고,
구분은 탭(\t)으로 됩니다.

---

# Slide 14

다음은 GUI 설계입니다.

GUI는 일관성, 가독성, 접근성, 직관성을 중심으로 설계했습니다.  
화면 간 폰트, 정렬, 색상을 통일했고, 흰색 카드와 색상 대비를 사용해 사용자가 정보를 보기 쉽게 했습니다.

또 학생과 조리사 버튼 배치, 장소별 탭 동선을 명확하게 구성해 초보자도 쉽게 사용할 수 있도록 했습니다.

화면 구성은 MainFrame 시작 화면, StudentFrame 학생 조회 화면, CookFrame 조리사 관리 화면으로 나뉩니다.

---

# Slide 15

마지막으로 예외 처리입니다.

파일이 없거나 읽기, 쓰기에 실패할 수 있기 때문에 try-catch로 처리했습니다.  
또 재고 입력값이나 운영 시간 형식이 잘못될 수 있어 입력값 검증도 추가했습니다.

파일 데이터 형식이 맞지 않는 경우에는 해당 행을 무시하거나 null 체크를 통해 오류를 줄였습니다.  
이를 통해 프로그램이 갑자기 종료되지 않고 안정적으로 동작하도록 구현했습니다.
